# Docker-песочница для агента

Весь агент (planner-клиент + инструменты + исполнение скриптов) работает
**внутри контейнера**. Единственное что видно снаружи — папка `./workspace`
на хосте, смонтированная как `/workspace` внутри контейнера. Всё остальное —
pip install, системные пакеты, попытки агента полезть куда-то ещё внутри
контейнера — остаётся внутри и исчезает вместе с контейнером при пересборке.

## Настройка

1. Создай `.env` в корне проекта (рядом с `docker-compose.yml`):
```
AGENT_COLAB_URL=https://твой-текущий-туннель.trycloudflare.com
AGENT_GROQ_API_KEY=твой_ключ
AGENT_APPROVAL_MODE=ask
```

   Про `AGENT_APPROVAL_MODE`: раз контейнер одноразовый и не может задеть
   хост-систему, `auto` тут разумнее чем на голой машине — но это твой
   осознанный выбор, не дефолт. Начни с `ask`, переключи на `auto` когда
   убедишься что контейнер реально держит периметр.

2. Cloudflare-туннель меняется при каждом рестарте Colab-ячейки —
   обновляй `AGENT_COLAB_URL` в `.env` после каждого рестарта, пересборка
   образа для этого не нужна (env читается при старте контейнера, не при сборке).

## Запуск

```bash
mkdir -p workspace   # папка проекта, которую видит агент
docker compose up --build
```

Первый запуск соберёт образ (~минута), дальше `docker compose up` быстрее,
раз образ уже собран.

## Что реально изолировано

- Файловые операции агента физически не могут выйти за `/workspace` внутри
  контейнера (тот же `path_guard`/`self_guard` работают и внутри Docker —
  это не замена, а дополнительный слой)
- `pip install`/apt-пакеты которые агент решит поставить — остаются внутри
  контейнера, не засоряют твою реальную систему
- Если контейнер что-то сломает у себя внутри — `docker compose down` и
  `docker compose up --build` даёт чистый старт, хост не тронут

## Что НЕ изолировано

- Сетевой доступ — агент внутри контейнера всё ещё может стучаться в интернет
  (Colab, Groq, что угодно ещё если решит). Полная изоляция сети потребует
  отдельного прокси с allowlist на конкретные домены — это не 'из коробки'.
- Файлы в `./workspace` на хосте — агент может писать/удалять что угодно
  внутри этой конкретной папки, она реальная, не эфемерная как остальной
  контейнер. Не клади в `workspace/` ничего кроме тестовых проектов.
